# ADR-025 · 增量运行：sink 级指纹失效（`decodehub run --incremental`）

- 状态：已接受（2026-09-05）
- 背景：用户场景——"只更新了示波器 CH1 的数据，其余不动"。`decodehub run`
  原语义永远全量重算（正确但不省）：无跨 run 记忆，系统无法判断哪些产物
  仍然新鲜。会话内 memo（`_inherit_memo`）只覆盖单次会话的参数级复用，
  跨 run 的文件级增量是空白。

## 决策

1. **失效单位 = sink**（锁/管线报告），不是采集集。每个 sink 的指纹 =
   SHA256(依赖闭包 ⊕ 配置)，闭包与指纹覆盖：
   - 依赖**源文件内容哈希**（锚依赖传递：downlink ⊇ uplink 的源文件——
     上行帧网格变了，下行槽位对齐必须重算，闭包从 `requires_sync` +
     `uplink_source` 自动推导，无需人工声明）；
   - 锁参数/实例名、管线链定义（链上链传递：tap 的指纹进下游指纹）；
   - 命名模板、导出/渲染配置、tool_version（产物形态变了 = 全失效）。
2. **manifest.json**（采集集目录，内部契约不参与命名模板）：记录每个 sink 的
   指纹、计数（total/errors/by_kind）与产物文件清单。二次运行比对指纹 +
   核验产物文件仍在 → 未变 sink **跳过**（旧产物原地沿用，连源摄取都省）；
   指纹变了 → 只重算该子图。
3. **decoded.json 拼接**：机器汇总是采集集级、含全部报告——重算 sink 出新
   报告，跳过 sink 的报告从旧 decoded.json 原样搬入（旧文件缺失 → 退回
   全量）。index 的"增量"列与 summary 的 `rerun_sinks/skipped_sinks`
   向 CI 报告重算/跳过数。
4. **保守边界**：tap 无法唯一定位的管线（缺省 tap + 多锁）键记 `*|名`
   ——永不命中 manifest = 恒重算，且依赖记全量源（全量摄取）。`--incremental`
   为显式 opt-in；不带该参数的全量 run **同样写 manifest**（为后续增量留档）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 采集集级失效（任一文件变 → 整集重算） | 粒度太粗，"只更新 CH1"会冤枉整集 |
| mtime 判变化 | 拷贝/触摸即误判；内容哈希才是语义 |
| 跨 run 持久化 memo（事件级） | 收益边际递减且泄漏会话语义；sink 级文件增量已覆盖实际诉求 |
| 默认开启增量 | 首次语义变化（旧产物沿用）对 CI 是惊吓；显式 opt-in + `--force`式全量（不带 flag）并存 |

## 后果

- 正面："只更新部分数据"从全量重算变为定向重算（示例：4 锁 3 管线里动
  一个文件只重算 2 个 sink）；锚耦合自动传播，无需人工声明依赖；
  manifest 让"这批产物依据什么输入产生"首次可审计。
- 负面：重锁拒绝语义下，增量路径与 `run_decode` overrides 重建共用
  "先 pop 后重建"约定；哈希开销 O(采集文件体积)（1MB/s 量级，可忽略）；
  tap 歧义管线恒重算（正确性优先）。
