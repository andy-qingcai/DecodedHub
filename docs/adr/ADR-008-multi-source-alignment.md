# ADR-008 · 多源工程：从"时间对齐合并"到"并行独立分析"（v1.2 修订）

- 状态：已接受，v1.2 修订（2026-09-03）
- 背景：一个实验中多台采集器（LA / 示波器 / MCU ADC）同时各采多路信号。

## v1.2 修订（用户约束更新，取代 v1.1 的合并主线）

用户补充的两项现实约束：

1. **一条通讯的各线不会拆到多台设备**（SCL/SDA 永远在同一台设备上）——跨源混合解码不是目标场景；
2. **PC 侧时间戳有 ≥ 百毫秒误差**——墙钟对齐在真实环境无意义，跨设备时间同步整体不可行。

**裁决**：多源的价值不是"共时间轴"，而是**一个会话并行管理多路独立采集**：

- **每源独立协议锁与解码报告**（`SessionState.locks/reports: dict[alias, …]`）——各源可锁不同协议（LA 锁 I2C、另一台锁 UART），互不影响；
- `lock_protocol / run_decode / get_events / export_events / render_* / inspect_graph / unlock_protocol` 均带 `source` 参数（唯一源可省；多源必填，缺省调用得到引导性错误）；
- `run_decode()` 缺省 = **一次并行解码全部已锁源**，返回分节摘要；
- `add_source` **不再使协议锁失效**（各源时间轴独立，新增源不影响已锁源）；
- **`set_alignment` 从工具层移除**：合并/对齐（`Project.merged` + 手动偏移 + 墙钟差值）保留为**库能力**（有单测锚定），不占工具上下文；
- 工具数演进调整为 **4 → 8 → 15**。

## 历史（v1.1，库能力保留部分）

`Project` 聚合与 `merged()` 合并器仍存在并受测试保护（多源通道 `别名:` 前缀、同时刻容差归并、≤32 通道限制、偏移记忆化）。若未来出现真实可对齐的场景（如硬件同步线），可基于此库能力重新暴露工具。

### v1.1 已否决项（继续有效）

- **锚点对齐**（跨设备共同信号自动检测）：用户裁定其场景不可得，永久否决；
- 图引擎多 capture 输入；漂移拟合（依赖锚点）。

### 浮点噪声坑（v1.1 实现期发现，库能力仍受益）

跨源合并时"同一物理时刻"的两条边经浮点运算/CSV 往返后相差 ~1e-18s，I2C 会把伪先后误判为
大量伪 START。修复 = 合并器同时刻容差归并（≤ max(1e-12, 1e-12·|t|) 秒，比 200MHz LA 的
5ns 粒度低 6 个数量级）。回归：`test_cross_device_via_csv_roundtrip`。

## v1.1 原始决策（现作为库能力实现规范保留）

1. **`Project` 聚合**：N 个 `SourceEntry`（别名 + Capture + offset），工程时间 = 源时间 + 偏移；参考源 = 首个源。
2. 对齐方式：手动偏移（增量合并）或墙钟差值（`t_wall`）——**均为库接口，不在工具层暴露**。
3. **`merged()` 合并单一 Capture**（按 (capture_ids, offsets) 记忆化）：多源通道名 `别名:` 前缀；单源向后兼容；数字通道 ≤ 32；同时刻容差归并（见文末）。
4. ~~对齐/源变更使协议锁失效~~ → v1.2 起各源独立，`add_source` 不再影响任何锁。

## 明确否决

| 方案 | 否决理由 |
|---|---|
| **锚点对齐**（跨设备共同信号检测：同步脉冲互相关 / 协议事件锚点） | **用户裁定其场景不可得**（不同设备看不到共同信号、无法布同步线）；相关自动检测代码全部不做 |
| 图引擎多 capture 输入（每 pick 节点声明源） | 保留现有单 capture 端口语义；若未来需要再评估 |
| 漂移拟合（双锚点线性修正） | 依赖锚点，随之延后；TimeTransform 保持纯 offset |
| v1.2：把合并/对齐暴露为工具（set_alignment） | 用户环境 PC 时间戳 ≥百 ms 误差且不拆总线到多设备——合并无可信偏移来源，暴露只会浪费工具上下文与诱导误读 |

## 浮点噪声坑（实现期发现，库能力仍受益）

跨源合并时，"同一物理时刻"的两条边经 `−off + off` 或 CSV 十进制往返后相差 ~1e-18s。
I2C 语义中"SCL 高时 SDA 变化 = START"会把这种伪先后误判为大量伪起始条件
（单源路径无此问题：from_segments 把同时翻转合成同一快照）。
修复 = 合并时按容差归并同时刻翻转（容差比最小真实特征——200MHz LA 的 5ns 粒度——低 6 个数量级）。
回归测试：`test_cross_device_via_csv_roundtrip`。

## 后果（v1.2）

- 正面：一个会话并行管理多采集器——各源独立锁协议（可不同）、`run_decode()` 一次解码全部、按源取事件/渲染/导出（制品目录天然按 capture_id 隔离）；追加源零破坏；工具 4 → 8 → 15。
- 负面：跨源没有公共时间轴（如实反映现实——不可同步就不假装同步）；多源时工具必须带 `source`（缺省得到引导性错误）。
