# ADR-012 · 协议模块化：一协议一目录（编码 + 解码 + 原理文档同处）

- 状态：已接受（2026-09-03）
- 背景：用户批评——编码器全部耦合在 synth.py 一个文件；协议（i2c/spi…）的编解码应各自
  拆分文件，且每个协议需附带说明**编解码原理**的 markdown 文档。

## 决策

```
decode/protocols/<协议>/
├── decode.py    # 解码节点（@register；图的原数据传递消费端）
├── encode.py    # 合成编码器（往返测试的编码方向，注入抖动/噪声/漂移）
├── README.md    # 编解码原理：波形模型 / 发送侧编码 / 接收侧算法 / 参数 / 事件 / 测试锚点
└── (vendored)   # uplink/dsss.py、downlink/dpsk.py 等零改动搬运的接收机
```

- **编码与解码成对同目录**：往返测试的两端物理相邻，改协议时一处可见全貌
  （此前解码在 nodes/<p>.py、编码全部挤在 synth.py——即用户指出的耦合）。
- **文档随代码走**：协议 README 与实现同目录同评审；`docs/41-decode.md` 退化为
  索引（图模型/端口/事件基类保留，算法细节指向各协议 README）——避免双处漂移。
- `decode/nodes/` 只留**通用节点**（picks/slicer/filters——非协议）；`decode/synth.py`
  变为兼容门面（再导出全部 encode_* + 通用助手 analogify/save_kingst_csv），
  既有测试/examples 导入路径不破坏。
- `protocols/_shared.py`：协议节点公共辅助（模拟通道挑选/均匀性校验），
  消除跨协议私有导入（downlink 曾 import uplink 的私有函数）。
- 扩展指南更新为新协议三件套（见 docs/30）：引擎/网关/呈现零改动的承诺不变。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 只拆 synth.py 为 synth/ 目录（编码仍与解码分离） | 半途而废——编解码仍不在一处，加协议要改两个目录 |
| 协议包同时收纳图模板/目录条目 | 应用层编排（PROTOCOL_CATALOG）与领域实现分层更清晰；避免 protocols 反向依赖 app |
| 删除 synth 门面、全量改调用方 | 6+ 个测试/demo 文件纯机械改动，门面零成本保留兼容 |

## 后果

- 正面：协议自包含（代码+测试矢量生成+原理文档）；新增协议的产物明确
  （三件套 + 一行注册 + 目录一行）；文档漂移面缩小到协议目录内。
- 负面：目录层级 +1；synth 门面是长期兼容层（新代码应直接 import protocols.*）。
- 迁移为纯机械移动（函数体零改动），127 个测试全过即等价性证明。
