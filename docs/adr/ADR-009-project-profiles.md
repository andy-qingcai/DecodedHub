# ADR-009 · 工程档案（Profile）：固化"源定义 + 协议锁"

- 状态：已接受（2026-09-03）
- 背景：用户场景——已定型的项目，**调试 IO 有限且固定、录制仪器固定**，天天重复"抓取→分析"。
  每次会话都重新 lock_source/add_source/lock_protocol/参数映射是纯浪费，也浪费 LLM 上下文。

## 决策

1. **Profile = 会话配置的持久化快照**（应用层，`app/profile.py`）：
   `profiles/<name>.json`（版本字段 + 人可读 JSON）：
   - `sources`: [{alias, format, options}] —— 仪器固定 → 格式与选项（sample_rate 等）固化；
   - `locks`: [{source, protocol, params}] —— IO 固定 → 协议参数与**通道角色钉死**
     （如 `{"scl": "D0", "sda": "D1"}`、`{"rx": "TX"}`）。
   - **文件路径不固化**（每次采集都换）。
2. **工具**：`list_profiles` / `open_project`（DISCOVERY 阶段）+ `save_profile`（SOURCE_LOCKED 起）。
   工具演进 **6 → 11 → 18**（含累积可见性）。
3. **`open_project(profile, files={别名: 路径})` 一步直达 READY**：摄取各源 → 应用全部协议锁 →
   可直接 `run_decode`。重复调试会话从约 6 次交互降为 2 次。
4. **接线防线**：档案钉死的通道角色在打开时校验——采集通道集合与档案不符（探头插错位）
   → 立即报错并列出实际通道，而不是解出乱码后才发现。防线依赖角色显式钉死
   （自动映射无法区分"接线变了"与"本来就没指定"）。
5. **可移植**：档案是普通 JSON，可提交进固件仓库、跨机器/团队成员共享。
   目录约定 `./profiles/`（可用环境变量 `DECODEHUB_PROFILES_DIR` 覆盖）。
6. 会话占用检查：`open_project` 要求空会话（已有源则提示先 `reset_session`）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 档案固化文件路径 + 定时重读目录 | 路径每次换；自动发现会抓错文件，显式 files 更安全 |
| 档案进 MCP resource（客户端浏览） | 增加资源面；list_profiles 文本已够用且更省事 |
| 服务端记忆上次会话（隐式档案） | 隐式状态违背"会话即状态"模型；显式命名档案可版本化可共享 |
| 档案包含渲染默认值（时间窗/帧数上限） | YAGNI，渲染参数随问题而变，不是"固定仪器"的一部分 |

## 后果

- 正面：重复调试一步开工程；接线错误前置暴露；档案可 git/共享；save 时源选项
  （sample_rate 等）随 SourceEntry.options 一并固化，重开无需重输。
- 负面：档案与实际接线可能漂移（固件改板后忘更新）——打开时的通道校验是最小防线；
  档案版本高于当前支持时明确拒绝（前向兼容留给未来迁移逻辑）。
