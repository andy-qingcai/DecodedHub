# ADR-024 · 产物命名与路径模板化（`[runs.X.naming]` / `out_dir` / `set_dir`）

- 状态：已接受（2026-09-05）
- 背景：headless CLI（ADR-015）把解码产物固定为 `reports/<run>/<label>/decoded.json`
  等缺省名。团队集成（CI 断言、报告归档、多运行并行写同一仓库目录）需要
  自定文件名与目录层级，此前只能跑完后搬文件——产物路径不可配置，`decodehub.toml`
  就还差最后一块"输出布局"没固化。

## 决策

1. **`[runs.X.naming]` 六个命名模板**（缺省值 = 原行为，完全向后兼容）：

   | 键 | 缺省 | 可用占位符 |
   |---|---|---|
   | `decoded` | `decoded.json` | `{label}` `{run}` |
   | `events`  | 空 = 智能命名（单报告 `events.<ext>`，多报告带 `源-协议`） | `{source}` `{protocol}` `{ext}` `{label}` `{run}` |
   | `timing`  | 空 = `timing_{n}.png` | `{source}` `{protocol}` `{n}` `{label}` `{run}` |
   | `analog`  | 空 = `analog_<通道>_{n}.png` | `{source}` `{channel}` `{n}` `{label}` `{run}` |
   | `index`   | `index.md` | `{run}` |
   | `summary` | `summary.json` | `{run}` |

   配置示例见 docs/70-headless-cli.md"产物命名与路径模板"一节。

2. **运行级路径**：`[runs.X]` 新增 `out_dir`（运行级产物根，覆盖 `[project]` 的
   `out_dir`；CLI `--out` 仍最高优先）与 `set_dir`（采集集子目录模板，如
   `sets/{label}`，可嵌套子目录 `by_day/{label}/v1`）。产物布局变为
   `<out_dir>/<run>/<set_dir 展开>/<naming 模板展开>`。

3. **占位符白名单严格校验**（与整份配置的未知字段报错同风格）：每键允许的
   占位符集合固定（上表），未知占位符与未知键在 `load_config` 时即报错并列出
   可用项——拼写错误绝不静默落成字面花括号文件名。`{label}` 由批量展开的采集集
   标签替换，`{run}` 为运行名。

4. **单一实现点**：runner 在采集集执行时统一 `format(**ctx)` 后把最终文件名
   传给 `export_events` / `render_timing` / `render_analog`（后两者新增
   `filename` 参数）；应用层 services 只接受显式文件名，不感知模板语义。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 散落各处的硬编码文件名（现状） | CI/归档只能事后搬文件；多运行写同一目录互相覆盖；产物布局无法进配置评审 |
| 全局唯一命名（时间戳/UUID 前缀） | 文件名不可预测，CI 断言与人工查阅都要先 glob 再猜；且"每次运行都全新目录"与增量运行（ADR-025）的原地沿用语义冲突 |
| 单一大模板（如一条完整路径模板） | 一个字符串同时编目录与文件名，占位符含义耦合；按键拆分后各键白名单更小、报错更准 |
| 事后 rename 钩子（run 完按模板改名） | 两套真相（内部名 + 展示名），增量/断点续跑时中间状态暴露给用户；失败模式多一整类 |

## 后果

- 正面：产物布局成为配置的一部分——可评审、可复现；同一工程多运行并行写
  互不干扰；CI 直接断言模板化路径。缺省零变化，老配置不需要迁移。
- 负面/边界：模板变了 = 产物形态变了，增量运行（ADR-025）指纹把 naming 配置
  纳入计算——改模板即全量重算（正确而非巧合）；占位符集合是封闭的，新占位符
  （如 `{date}`）需要改白名单而非用户侧绕路。
