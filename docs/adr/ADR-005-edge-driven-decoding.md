# ADR-005 · 解码基于跳变流而非均匀重采样

- 状态：已接受（2026-09-03）

## 决策

所有协议解码器消费 `DigitalWave` 的**跳变流**（`edge_stream`/`level_at`），位采样 = 在目标时刻二分查电平；**不做**"重采样到统一网格"的预处理。

## 理由

1. **跨源无感**：200MHz LA 与示波器切片输出（可能 ~MHz）走同一代码路径；解码算法只关心"时刻 t 的电平"与"边沿时刻"。
2. **时钟拉伸免疫**：I2C 从机拉低 SCL 时，位采样只在**实际** SCL 上升沿发生——无需超时/重试逻辑（sigrok 同思路）。
3. **性能**：O(跳变数×log) 而非 O(采样数)；1M 采样毫秒级。
4. **精度**：跳变时刻保留源的原始时间分辨率（如 kvdat 的 5ns 索引粒度），重采样会引入网格量化误差。

## 采样时刻的确定（与重采样区分）

- UART：起始位中点锚定 + 纯算术推进（`ts + (k+0.5)×bit_T`），`level_at` 查询；
- I2C：采样时刻 = SCL 上升沿本身（事件驱动，无合成时刻）；
- SPI：采样时刻 = 采样沿本身（CPOL/CPHA 查表）。

只有 UART 需要"合成采样时刻"，且重同步仅发生在起始位（等值位连发无沿可同步；≤12 bit 内时钟漂移 ≪ 半 bit——sigrok 同实践）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 均匀重采样到 16×波特率网格 | 引入量化误差与 O(采样数) 成本；对示波器低采样率源欠采样直接失真 |
| 逐采样状态机（bool 数组扫描） | 同上；且与 ADR-003 的紧凑 IR 相悖 |

## 后果

- 正面：算法简洁（事件循环 + 二分查询）；跨源正确；天然支持拉伸/变速时钟。
- 负面：`level_at` 的 O(log E) 在极端边沿数（噪声毛刺百万级）下需注意——由 slicer 滞回阈值在上游抑制毛刺（这是滞回参数存在的另一理由）。
