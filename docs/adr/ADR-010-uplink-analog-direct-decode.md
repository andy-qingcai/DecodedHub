# ADR-010 · 上行（uplink DSSS）接入：模拟直达解码 + 算法搬运

- 状态：已接受（2026-09-03）
- 背景：把 `原vendored工程`（实机调参过的上行 DSSS 接收机）接入平台。
  用户明确指出：这类解码**需要图的原数据（原始模拟）传递方式**。

## 协议要点

上行 = 每 60Hz 周期一个 ~248µs 突发帧的 DSSS：31-chip m 序列（0x3DA60E45）扩频、
每 bit 一个完整 PN、双极性 NRZ、码片标称 1µs（实测 0.9692µs，接收机自动估计）。
帧 = 前导 001 + 5 数据 bit = 8 符号。信号骑在强 60Hz 包络上，占空比 1.5%。

## 决策

1. **算法搬运（vendored），DSP 零改动**：`decode/nodes/uplink_dsss.py` = 原项目
   config.py + dsss_rx.py 原样拼接（注明出处）。这些参数（MAD 门限、梳齿窗口完整性、
   LSQ 亚样本精化、候选仲裁）在真实信道上验证过——"改进"即回归风险。
   预条件/相关/分段/同步/仲裁全链条保留，包括**纯噪声诚实拒绝**语义。
2. **模拟直达图路径**（本 ADR 的核心）：
   `apick → uplink_precond(analog→analog) → uplink_decode(analog→events)`。
   **不经 slicer**——DSSS 解扩需要幅度软信息（PN 相关值），一位切片毁掉全部信息。
   这验证了端口类型系统的设计初衷：`analog` 与 `digital` 是两种一等数据；
   模拟→数字唯一路径是 slicer，而**模拟→解码器**是合法且必要的第二条路。
   uplink_precond 独立成节点的理由：抽取+包络剥离是可复用、可检视的信号整理步骤
   （inspect_graph 可见），且未来其他模拟域协议（下行 DPSK）可复用其输出。
3. **解码器极性自适应**（帧同步搜索 ± 极性）→ 平台不提供"自动极性"参数；
   invert/unipolar/msb_first 保留为排查旋钮（对应原 CLI 的 --invert/--unipolar/--no-msb-first）。
4. **协议扩展点 = profile**：新 PN/帧形（如 pn63）在 `UPLINK_PROFILES` 加条目，
   工具参数 `profile` 引用；前导通过率仲裁天然支持多档案逗号尝试（v1 暴露单档案）。
5. scipy 进入依赖（FFT 相关/多相重采样/形态学滤波），pyproject 已加 `scipy>=1.11`。
6. 事件模型：`UplinkEvent(kind="uplink.frame"|"uplink.warn")`，t_start 归一到采集
   时间轴（含 MHO98 负 t0）；warn 事件携带接收机诊断（码片偏差/拒绝原因），
   延续"错误是事件不是异常"（ADR-004）。
7. 渲染：模拟直达协议无数字波形 → `render_timing` 自动回落为
   **原始模拟波形 + 帧突发 span 叠加**（analog_plot 新增 events 参数）。

## 已知边界（如实记录，不修 vendored 代码）

- 捕获起点 × 时钟偏差（ppm）组合下首个数据帧可能错位（测试 `test_chip_ppm_30800`
  注明）；真实信道帧居中/单突发，实测不受影响（黄金 `test_golden_24ms` 全对）。
- 单帧连续模式（248µs）相关面不足解不出——接收机面向突发或长连续流。
- 末尾齿因窗口完整性要求可能丢弃至多一帧（边界语义）。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 依赖原项目包（sys.path/安装） | 平台自含性破坏；原项目无打包；升级漂移不可控 |
| 重写/优化 DSP | 参数是实机调参结果，任何"改进"都是未经验证的回归 |
| 单一 uplink 节点（含预条件） | 丢失可检视的中间形态；预条件无法被未来模拟域协议复用 |
| 切片后做"数字相关" | 一位切片毁掉幅度软信息——协议不可解 |

## 后果

- 正面：第 4 个协议且是首个**模拟域**协议，图的"原数据传递"价值落地；真实采集
  （1M 点 50MSa/s）0.1s 解码，黄金输出与原项目 `real_out.json` 一致（0x01）；
  与工程档案（ADR-009）组合可用。
- 负面：scipy 依赖；vendored 文件约 500 行不受平台测试风格约束（由行为测试锚定）；
  下行 DPSK（dpsk_rx.py）未接入——待下行格式确认后按同一模式扩展。
