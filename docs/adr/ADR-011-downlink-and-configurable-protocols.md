# ADR-011 · 下行 DBPSK 接入（上行为锚的偏移解析）+ 协议参数全量可配

- 状态：已接受（2026-09-03）
- 背景：用户指出两点——① 原项目中"根据 uplink 做偏移解析的 dpsk"去哪了（ADR-010 曾搁置）；
  ② uplink/downlink 协议参数在文档中被写成定值，这是不对的，必须可配置。

## 决策一：下行接入 = 图的跨节点扇入 + 跨源注入

协议：263kHz 方波载波 DBPSK、10 载波周期/bit、每包 1 起始位（相位参考）+ 16 数据位；
**每上行帧周期 6 个包，槽位挂在上行 60Hz 帧网格上，锚点偏移 delta 由能量扫描逐包自校准
（固件标称偏移参考点与线上实测差 ~1.8ms，绝不假设）**。解调 = 延迟线鉴相（无需载波相位），
逐包 fc 估计 + 双簇共识仲裁 + 槽位角色轮转（恒载波包定位对端周期末位）。

图结构（本 ADR 的核心）：

```
源A(上行通道) → apick → uplink_precond → uplink_decode ──┐（events: 上行帧起点）
                                                          ▼
源B(下行通道) → apick ──────────────────▶ downlink_decode(in: analog, sync: events)
```

- **扇入**：downlink_decode 是首个双输入解码节点——`analog`（本源原始波形）与
  `events`（另一解码器的输出）在一个节点汇合。线性管道无法表达，这是 DAG 的本义。
- **跨源注入**：`ProtocolLock.source_inputs = {节点→源别名}`；run_decode 按此把多个
  Capture 注入同一张图。下行锁的图**内嵌上行子图**（锁定时克隆）——上行锁后续变化
  不追溯影响，重锁下行即刷新。
- **一源多协议锁**：锁键 = `源|协议`（示波器双通道单源可同时锁 uplink+downlink）；
  工具的 source 参数辅以可选 protocol 消歧；报错引导按场景提示 source/protocol。
- **同触发校验**：上行/下行 t0 相差 >1ms 即拒绝（下行锚定要求两通道来自同一次采集；
  跨仪器对齐被 ADR-008 v1.2 裁定不可行，此处不放松）。

## 决策二：协议参数全量可配（默认 ≠ 常量）

- **上行工具参数**：`profile / chip_s / pn_word(0x 前缀) / pn_len / pream(位串) /
  data_bits / invert / unipolar / msb_first`；**下行**：`profile / fc_nominal /
  cycles_per_bit / n_bits / slot_offsets_us(列表) / frame_hz / invert`。
  新 Param 类型：hexint / bits / float_list。原 CLI 的全部排查旋钮均有对应。
- **策略超参留在档案层**（UPLINK/DOWNLINK_PROFILES，代码内一处登记）：
  数十个 DSP 门限作为工具参数会淹没 LLM 上下文——档案 = 形状 + 配套策略的整体。
- **物理约束（如实记录）**：PN 字必须具 m 序列级近零旁瓣自相关（7-chip 随机字实测
  不可解）；默认策略按 31-chip 实机调参，**改 PN 长度需配套新档案**（已验证可行轴：
  同长度换 m 序列字、数据位数、码片速率、极性、载波/周期数/包长/槽位结构）。
- delta（锚点偏移）**不可配**——它本来就不是参数，是接收机逐包自校准的测量量。

## 已知边界

- 恒载波包的差分读出可能为全 0 或全 1（差分极性两极），接收机同时给出
  `data_hex_inv`；事件模型以 value / value_inv 双字段保留。
- 帧编号为网格索引（可与真值整体差一），跨帧比对按 (frame,slot) 邻接对齐。
- vendored DSP 零改动原则延续 ADR-010。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 下行独立解码（自找包边） | 时序模型本质锚定上行网格；无锚时多发射机无法分辨槽位 |
| 下行走"读上行报告再喂参"的两步工具流 | 跨工具传递中间结果违背图的原数据传递初衷；一次 run_decode 全链路 |
| 全部 DSP 策略旋钮暴露为工具参数 | 上下文经济性（平台初衷）；档案层一处登记更可控 |
| 同源上/下行互斥单锁 | 示波器双通道单源是天然场景，必须并存 |

## 后果

- 正面：上/下行成对解码一步完成（run_decode 缺省跑全部锁）；协议形状按设备实况
  配置并随工程档案（ADR-009）持久化；图引擎验证了 events×analog 扇入与多源注入。
- 负面：锁/报告键从源别名变为 `源|协议`（对外工具参数不变，内部与测试可见）；
  下行锁内嵌上行子图使其图较大（inspect_graph 可读但更长）。
