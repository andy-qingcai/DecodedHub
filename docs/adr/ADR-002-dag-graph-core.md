# ADR-002 · 解码流水线 = 显式 DAG（拉式记忆化求值）；渲染/导出置于图外

- 状态：已接受（2026-09-03）
- 背景：用户明确要求"graph node 形式传递数据，因为解析可能非常复杂"。

## 决策

**图内**（纯函数子图，数据加工）：`capture → digital_pick/analog_pick → slicer → 解码器 → event_filter`。

执行语义：拉式（pull-based）记忆化求值——递归下降即拓扑序，只计算目标节点的祖先，输出按节点 id 缓存；图不可变（参数变化=新图，上游自动命中缓存）。

**图外**（呈现层服务，副作用子图）：Markdown 表 / PNG / 文件导出 / 制品登记。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 线性管道（阶段数组） | 无法表达 I2C 的双线扇入（scope → 2×切片 → SCL+SDA）与多汇输出；复杂解析正是用户痛点 |
| 可组合函数（pandas 风格） | 可行但无内省：无法做端口类型验证、局部重算、`inspect_graph` 给 LLM 检视 |
| Node-RED 式推送/调度器 | 面向流式；离线解码不需要队列与调度，白增复杂度（估计 >3× 代码量） |
| 导出/渲染也做节点 | 双代码路径风险（工具直取 vs 图执行结果不一致）；副作用破坏纯函数缓存语义 |

## 关键裁决细节

1. **端口类型严格相等，无隐式转换**——模拟→数字必须显式过 `slicer`（把阈值决策变成图中可见、可检视的节点，错误可定位到节点）。
2. 协议角色名（`scl/sda/rx`）在**图模板构建期**解析为具体通道名——图内无运行期名字查找，保证纯函数与可序列化（`inspect_graph` 输出稳定）。
3. 引擎预算 ~150 行：无调度器、无队列、无增量失效（v1 图一次性求值；"改参数重解码"通过重建解码节点并复用上游缓存实现）。
4. 合成波形发生器**不注册为节点**（随机性/非确定性违反纯函数契约），作为测试库函数存在。

## 后果

- 正面：复杂解析可组合、可验证（5 条构建期规则）、可缓存、可被 LLM 用 `inspect_graph` 诊断；解码上下文可脱离文件系统单测。
- 负面：极简场景（单通道直解）也需建图——由应用层图模板屏蔽（`lock_protocol` 一调用自动成图），用户无感。
